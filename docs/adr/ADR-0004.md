# ADR-0004: Spring Boot, MCP, Apigee, and Hexagonal Boundaries

**Status**: Accepted  
**Date**: 2026-08-04

## Context

The platform needs enterprise backend maturity, interoperable tool contracts, gateway-grade API controls, and long-term maintainable architecture boundaries.

## Decision

- Use Spring Boot for the backend service layer.
- Use MCP as the skill protocol standard.
- Use Apigee for enterprise gateway integration.
- Enforce hexagonal architecture in backend modules.

## Alternatives

- Quarkus / Micronaut for backend
- Vendor-specific tool calling APIs
- Kong / AWS API Gateway / NGINX-only edge
- Layered monolith without strict ports/adapters

## Rationale

The selected combination optimizes enterprise operability, portability, policy enforcement, and testability.

## Consequences

Interface contracts become explicit and adapter boundaries must be preserved in code reviews.
