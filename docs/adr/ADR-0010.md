# ADR-0010: Durable Runtime State via Portable SQL (SQLite Now, PostgreSQL Twin)

**Status:** Accepted
**Date:** 2026-10-04
**Refines:** ADR-0007 (PostgreSQL as the data foundation), ADR-0006 (single-use approvals)

## Context

Runs, consumed approvals and idempotency records lived in memory or in one JSON file per
run. Single-use approvals therefore did not survive a restart or span processes, and
listing runs scanned every file (~27 ms at 167 runs). The target store is PostgreSQL
(ADR-0007), but no Python PostgreSQL driver could be installed in this environment.

## Decision

1. One `SqlRuntimeStore` implements `CheckpointStore`, `ApprovalStore` and
   `IdempotencyStore` with portable SQL: bound parameters, `ON CONFLICT`, no
   dialect-specific functions. Statements live in one `STATEMENTS` table.
2. It runs on the standard library's `sqlite3` today (WAL mode, `BEGIN IMMEDIATE`) for
   local and single-node use. `ai/storage/sql/V001__runtime.postgres.sql` is the
   PostgreSQL twin; a test executes every statement on PostgreSQL via `PREPARE` so the
   driver swap is a connection-factory change (`SqlDialect`).
3. Single use is enforced by the database: consuming an approval inserts its id under a
   primary key, so concurrent processes cannot both consume it.
4. The agent service refuses to start without `COPILOT_STATE_DB` (durable runs required).

## Alternatives considered

| Option | Trade-off |
|---|---|
| Wait for psycopg | Keeps the restart/replica gap open with no verifiable progress. |
| Drive PostgreSQL through `psql` subprocesses at runtime | Fragile, slow and a command-execution surface; acceptable in tests only. |
| Redis for approvals | Another stateful service (ADR-0007 deferred Redis); weaker durability. |
| Hand-written Postgres wire client | A database driver is not something to own in this codebase. |

## Consequences

- Approval single use and idempotent replay now survive restarts (tested).
- SQLite serialises writes; it is a local/single-node store. Multi-replica deployments
  must use the PostgreSQL dialect once the driver is available (release checklist).
- Cross-process idempotent execution relies on single-use approvals plus the gateway's
  `Idempotency-Key`; a claim-row protocol can be added with the PostgreSQL store.
