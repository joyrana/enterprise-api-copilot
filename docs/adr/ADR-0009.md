# ADR-0009: Contract-First Platform API with a Local Reference Implementation; Standard-Library CLI

**Status:** Accepted
**Date:** 2026-10-04
**Refines:** ADR-0003 (CLI), ADR-0005 (service boundaries)

## Context

The Spring Boot platform owns the public API (ADR-0005) but cannot be built in the current
environment (Maven Central blocked), and the existing Go CLI depended on Cobra/Viper/
BubbleTea without a `go.sum`, so it could not be built either. Waiting would leave the CLI,
web app and agent unintegrated and untested.

## Decision

1. **Contracts first.** `contracts/openapi/platform-api.yaml` (public) and
   `agent-service.yaml` (internal, service-to-service) are the source of truth. Contract
   tests (`tests/contract/`) validate every response against them and fail if any
   documented operation is not exercised. They are implementation-independent.
2. **Local reference implementation.** `python -m ai.api platform` implements the public
   contract for development only. It refuses to start outside `local`/`test` mode, uses the
   same skill runtime and policy as the agent, and is the target the Spring Boot backend
   must match (same contract tests, pointed at the backend).
3. **Service-to-service auth.** The platform mints HS256 service tokens (audience
   `copilot-agent`, ≤5 min, principal in claims). The agent API accepts nothing else and
   never reads the principal from request bodies.
4. **Approve what you saw.** Approval requests must echo the displayed `action_hash`; a
   mismatch is a 409. Requesters without `approval:grant` get 403.
5. **CLI on the standard library only.** `flag`, `net/http`, `encoding/json`,
   `text/tabwriter`. No third-party modules, so no `go.sum` and no supply-chain surface.
   The UX (subcommands, `--output json`, exit codes) is implemented directly.

## Alternatives considered

| Option | Trade-off |
|---|---|
| Wait for the Spring backend | Blocks every client and the end-to-end workflow indefinitely. |
| CLI calls the agent directly | Violates "clients talk only to the platform"; duplicates auth. |
| Keep Cobra/BubbleTea | Nicer help/TUI; unbuildable here and adds dependencies for modest gain. |
| Python platform as the permanent backend | Contradicts ADR-0005; the facade is explicitly a dev stand-in. |

## Consequences

- The CLI, web client and agent are integration-tested today (`tests/system/`).
- Two implementations of one contract must be kept in step — the contract tests are the
  enforcement mechanism, so the Java backend must run them in CI before replacing the facade.
- The CLI has no interactive TUI; output is plain text or JSON.
- The run store for the facade is a file store (dev only); production runs belong to the
  platform database.
