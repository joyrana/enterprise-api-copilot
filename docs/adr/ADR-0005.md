# ADR-0005: Canonical Layout and Service Boundaries

**Status:** Accepted
**Date:** 2026-10-03
**Supersedes:** layout notes in README; partially supersedes ADR-0001 Decision 2 (Spring AI usage)

## Context

The repository had two Python agent trees (`ai/`, `agents/`), two skill layouts (grouped
`skills/api/discovery` and hyphenated `skills/api-discovery`), Spring AI with an OpenAI
starter in the Java backend, and an undefined `agent-service` in Compose. LLM provider
configuration would have lived in two languages, and the authority for authorization was
unspecified.

## Decision

1. **Python AI service** = packages `ai/` (agent + knowledge + models) and `skills/` (skill
   runtime + skills), deployed as one process. No per-node microservices.
2. **Spring Boot backend** is the control plane and the **policy decision point** (PDP).
   The Python skill runtime is the **policy enforcement point** (PEP) and calls the PDP
   through a `PolicyDecisionPort`.
3. **Model access lives only in Python.** Spring AI and the OpenAI starter are to be removed
   from the backend.
4. `agents/` and hyphenated skill directories are **deleted**. They had no importers other
   than `Makefile`/CI paths, which are migrated in the same change. Hyphenated directories
   were never importable as packages, so no runtime caller could exist.
5. Placeholder skills that raised `NotImplementedError` (`skills/docs` old server,
   `skills/github`) are removed rather than kept as fake capabilities. GitHub integration
   is deferred until a concrete use case and tests exist.

## Alternatives considered

| Option | Why not |
|---|---|
| Keep `agents/` shims | No callers; shims add a second import path and confuse ownership. |
| Make Spring Boot call the LLM via Spring AI and keep Python for graphs only | Two model configurations, two token-accounting paths, two prompt-injection surfaces. |
| Put authorization inside the agent | Violates "the model is never an authority"; the agent process is the most exposed component. |
| One microservice per agent role | Network hops and deployment surface with no isolation benefit; nodes share state. |

## Consequences

- The Python service needs an authenticated service-to-service contract with the platform
  (to be published in `contracts/openapi/agent-service.yaml` when the HTTP adapter lands).
- Until the platform is buildable, a local PDP (`LocalPolicyEngine`, explicit role →
  permission table) is used in dev/test. It is labelled as such in code and docs.
- Spring Boot must still be migrated off EOL 3.3.x; removing Spring AI reduces that
  migration's surface.
